# Git ve GitHub Dokümantasyonu

## 1. Temel Kavramlar

- **Git:** Dağıtık bir versiyon kontrol sistemidir. Tamamen yerel olarak çalışabilir.
- **Versiyon Kontrol Sistemi:** Projedeki dosyaların geçmişteki hallerini anlık görüntüler halinde kaydeden ve istendiğinde projenin eski bir anına geri dönülmesini sağlayan sistemdir. Kalabalık ekiplerin aynı dosyalar üzerinde sorun yaşamadan güvenle çalışmasını kolaylaştırır.
- **GitHub:** Git depolarının internet üzerinde saklandığı, paylaşıldığı ve yönetildiği bulut tabanlı bir depolama ve iş birliği platformudur, Microsoft’a aittir. Yazılımcılar için aynı zamanda açık kaynak projelere katkı sunulan ve portfolyo / CV niteliği taşır.
- **Repository:** Projeye ait tüm dosyaların, klasörlerin ve commitleri geçmişinin saklandığı veri tabanıdır. Git, dosya boyutlarını her değişiklikte sıfırdan katlayarak büyütmez; snapshot mantığıyla yalnızca farkları ve referansları saklayarak alanı oldukça verimli kullanır.
- **Commit:** Projenin o anki durumunun kalıcı olarak Git veri tabanına kaydedilmiş bir versiyonudur.
- **Branch:** Projede git init komutu ile versiyon kontrolünü başlattığımızda aslında varsayılan bir branch, master branch oluşur. Master branch ağacın gövdesi ise diğer branchleri dallar gibi düşünebiliriz. Branchler, projenin farklı versiyonlarının izlenmesini ve yönetilmesini sağlar. Varsayılan ana dal eskiden master olarak adlandırılırken günümüzde GitHub’da main ismini kullanmaktadır.
- **Merge:** Alternatif bir branch üzerinde yapılan geliştirmelerin ana dala veya başka bir dala güvenle birleştirilmesidir.
- **HEAD:** Git'in o an aktif olarak üzerinde çalıştığınız branch'i veya commit'i işaret eden imlecidir.

## 2. Terminal Araçları

- **git gui:** Grafiksel arayüz sunar; komut yazmadan repo klonlama, commit yapma veya inceleme işlemlerini tıklayarak yapmayı sağlar.
- **git cmd:** Windows Komut İstemi ortamında Git komutlarını çalıştırmaya yarar.
- **git bash:** Windows üzerinde Linux/Unix benzeri komut satırı deneyimi ve kabuk yetenekleri sunan terminaldir.

---

## 3. Temel Terminal Komutları

- `pwd`: O an bulunulan aktif dizinin tam dosya yolunu ekrana yazdırır.
- `ls`: Bulunulan klasördeki dosya ve alt klasörleri listeler.
- `ls -a`: Gizli dosyalar dahil her şeyi listeler.
- `cd ..`: Üst diziye döneriz.
- `cd`: İstenen klasörün içine geçiş yapar.
- `start (klasor_adi)`: Belirtilen klasörü Windows Dosya Gezgini arayüzünde açar.
- `clear`: Terminal ekranındaki tüm yazı geçmişini temizler.
- `touch (dosya adı)`: Yeni bir boş dosya oluşturur.
- `rmdir (klasor_adi)`: Yalnızca içi boş olan klasörleri siler.
- `rm -rf (klasor/dosya)`: Belirtilen klasörü veya dosyayı içindekilerle birlikte zorla ve kalıcı olarak siler.

---

## 4. Temel Git Komutları ve Kullanımları

- `git init`: Bulunulan dizinde sıfırdan bir Git deposu başlatır.
- `git status`: Takip edilen, değiştirilen, hazırlık alanına alınan veya henüz commit edilmemiş dosyaların anlık durumunu raporlar.
- `git add .`: Çalışma dizinindeki tüm yeni ve değiştirilmiş dosyaları stage taşır.
- `git commit -m "mesaj"`: Hazırlık alanındaki değişiklikleri bir açıklama mesajıyla yerel depoya kaydeder.
- `git commit -am "mesaj"`: Zaten takip edilen dosyalardaki değişiklikleri ayrı bir git add yapmadan doğrudan hem ekler hem commit eder.
- `git commit --amend`: En son yapılan commit'in açıklama mesajını veya unutulan dosya eklemelerini düzenlemek için editörü açar.
- `git restore --staged [dosya]`: Stage eklenmiş bir dosyayı commit öncesi hazırlık alanından geri çıkarır.
- `git rm --cached`: Dosyayı bilgisayardan silmeden, sadece Git'in takibinden ve staging alanından çıkarır.
- `git log`: Depoda bugüne kadar kaydedilmiş tüm commit geçmişini, yazarlarını ve tarihlerini listeler.
- `.gitignore`: Bu dosyanın içine yazılan dosya ve klasör isimleri Git tarafından kasten yok sayılır ve takibe/commite dahil edilmez.
- `git switch (branch adı)`: Belirtilen branch’a geçiş yapar.
